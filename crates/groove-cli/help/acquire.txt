EXAMPLES:
  groove acquire fix-nav --key nav-1
  groove acquire fix-nav -b main -w 30s --print-path
  groove acquire fix-parser -p frontend --key issue-42-attempt-1
  groove acquire investigate-flake --base main --wait 5s

Released slots with observed processes are skipped before cleanup. Stop lingering
shells, editors and builds; run acquire from outside any slot you want to reuse.
Git status warnings also prevent handoff: an incomplete final inventory is not a
verified clean checkout. Resolve the reported Git/filesystem issue before retrying.

Reserves a cleaned, verified checkout of --base (default HEAD) until it is
explicitly released. HEAD resolves where you run the command, so from a linked
worktree it is that checkout's commit. HEAD is detached in the reservation;
Groove never creates or switches branches. TASK names the reservation so later
commands can select it by label instead of the reservation UUID. An omitted TASK
gets a generated label. Labels use 1–128 ASCII letters, digits, dots, underscores
or hyphens, must not look like UUIDs, and are unique across the repository. An active label
cannot be reused: a second acquire with it fails with INVALID_ARGUMENT naming the
existing reservation and path. Keys must not contain control characters.
Select a pool with -p/--pool. Otherwise the owning workspace selects its pool,
then a repository with exactly one pool selects that pool. With several pools
outside a workspace, acquisition reports the available names and requires -p.

On macOS, unmount directories inside slots first: acquisition has no mount-table
safeguard. Linux checks visible mounts, including same-device bind mounts.

Cleanup follows the pool's policy: pristine (default) removes ignored files;
warm retains them only when reusing a healthy checkout. Retained files are not
validated build outputs and may disappear during rebuild. Run and validate your
build directly in the returned checkout. Build-tool caches outside pool roots can
survive pristine cleanup; the build tool owns their compatibility and sharing.
Cleanup repairs owner permissions on read-only directories before removing output.
Untouched tracked files keep inode and mtime. Files whose ctime changed since the
last verified checkout are rewritten, including metadata and hardlink changes.
This trusts that ctime cannot be backdated without root or a clock change.
Missing verification/index state, hidden index flags, attribute changes or a
large touched inventory force a full rewrite. Retained build outputs still need validation.
The marker and checkout must share one recognized filesystem; cross-filesystem
markers and override-only storage always use the full rewrite.

Capacity: a zero --wait scans once; a positive value bounds waiting for a
free slot (not checkout preparation, which has its own Git timeouts). There is
no FIFO fairness. On POOL_EXHAUSTED or ACQUIRE_TIMEOUT, wait or inspect with
`groove list`; never bypass capacity.
A Git preparation timeout stops the scan immediately with POOL_UNHEALTHY (exit 6).
Inspect that failure and increase --timeout for legitimately slow Git work.
Recognizable foreign repositories, moved worktrees and conflicting registration
claims at a slot path refuse preparation. Safely move the occupant back to its
original location or outside the pool before retrying; preserve its worktree
registration.

Retries: with --idempotency-key, repeating the same key, base and task
returns the original reservation without cleaning the checkout or resetting edits,
even across restarts or after the base branch moves. Changed inputs and
completed keys are rejected during retention: an idempotency key is remembered for
7 days after release. Background passes and pool destruction prune expired journals;
after pruning the key can allocate a new reservation. Use a new key per task.
Active reservations never expire. Permanent historical lock files are retained;
new keys and task labels use bounded shared lock sets.
Without a key, run `groove list` BEFORE retrying a lost response.

Acquisition prefers prepared spares, then existing verified checkouts, then empty
slots. These are hints: each selected checkout is still cleaned and verified.
Older checkouts without directory-metadata inventories rebuild once. Allow the
cold-checkout Git timeout for that first acquisition on a large repository.
Pools with ready_target start replacement preparation
in a separate process after reservation. Acquisition does not wait for replacement;
it still prepares/verifies its own requested base. Waiting for a currently preparing
spare counts against --wait, including a single scan with --wait 0s. Ready targets never
reduce reservable capacity and never expire a protected reservation.

--path-only prints exactly the workspace path and a newline in human mode.
The JSON acquisition response is unchanged by --path-only.
--wait requires a non-negative integer and a unit (ms, s, m or h), for example
--wait 30s. It defaults to 0s. --timeout defaults to the pool's saved git-timeout
(initially 2m) and must be positive. --key aliases --idempotency-key;
--print-path aliases --path-only. Legacy --task remains accepted with a warning.
