EXAMPLES:
  groove pool list
  groove pool list --all
  groove pool list --disk-usage
  groove pool create frontend --capacity 3 --cleanup warm
  groove pool create backend --capacity 2 --cleanup pristine
  groove acquire fix-navigation -p frontend
  groove pool delete frontend --dry-run

Acquisition selects an explicit pool, the owning workspace's pool, or the only
pool in that order. Several pools outside a workspace require an explicit name.
Names are 1..64 lowercase ASCII letters, digits, '_' or '-', starting with a
letter. Pool names are portable across case-sensitive and case-insensitive disks.
All linked worktrees share this catalog. Use --all to include deleted pools.
Interrupted pools (initializing or deleting) remain visible for recovery.

Returns at most 50 matching pools by default, ordered by name. Use --limit N,
--offset N or --unlimited. --all includes deleted pools and does not remove the
page limit; combine --all --unlimited for the complete catalog.
--sort state orders lifecycle state names lexicographically, then pool name;
--sort name restores the default order. Filtering and sorting precede pagination.
--order asc (default) or --order desc applies to both the sort key and pool-name
tie-breaker before pagination.
JSON includes pagination.total (after filtering), offset, limit (null with
--unlimited) and next_offset (null at the end). Metadata is still enumerated;
concurrent changes can shift offset pages. Disk usage scans only the returned page.

--disk-usage scans workspace contents (including ignored files), caches, logs and
history. Large pools can take time to scan. Sizes are logical file bytes; shared
Git objects and snapshots are excluded. Interrupted pools show '-' (storage:null).

Capacity, cleanup, checkout roots, idempotency keys, caches, history and
saved-release receipts are scoped to each pool. Keys stay tombstoned across reinit of
that same pool. Snapshots, branches, Git objects and repository configuration are
shared. Task labels are unique across the repository. Pools are not security
sandboxes; slot numbers are pool-local.

Deletion always requires an explicit pool name.
--pool-id checks a generation inside that namespace; it does not select a pool.
The original default pool keeps its existing directory and permanent locks.
Named pools live beneath <GIT_COMMON_DIR>/groove/pools/<name>/; their checkout
roots must not overlap another pool's published or pending root. Deleted pools
retain their current root claim until reinitialized with another root.
