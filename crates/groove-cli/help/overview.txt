WORKFLOW:
  groove pool init --capacity 4
  groove acquire --task fix-parser            # prints the path; work there
  # Work and run commands directly in the printed checkout path.
  groove release --save --task fix-parser     # snapshot, then free the slot

INSPECTION AND SETTINGS:
  groove pool list                     pool namespaces and lifecycle states
  groove pool list --disk-usage         compare pool storage sizes
  groove --pool frontend pool init --capacity 3 --cleanup warm
                                   create a separate workflow pool
  groove list                      active reservations
  groove list --slots              every slot, with status and next action
  groove show --task NAME          one reservation in detail
  groove snapshot list             local checkpoints
  groove pool set --capacity 8   grow the pool
  groove pool destroy --dry-run         preview deletion of an idle pool
  groove completions bash          print a shell completion script

Stop ALL writers, then release --save (snapshot, then release) or release. To keep
commits on a branch, create one yourself first; Groove never manages branches.
Reservations survive exits and crashes until explicitly released: there is no
expiry, daemon or implicit task execution. No command pushes or merges.
Worktrees share Git objects, refs and configuration; they are not security
sandboxes.
Explicit --pool NAME wins; otherwise pool commands select the current workspace's
owning pool (also via --repo), falling back to default outside managed workspaces.
Task labels/keys and capacity are pool-local; snapshots and branches are shared.
Destroy requires an explicit selection when several pools exist; see pool list --help.

Linux or macOS 13+, Git 2.40+, local storage (APFS on macOS).
Run groove COMMAND --help for examples,
defaults and recovery rules.

Slow queries show a spinner on interactive stderr. JSON and quiet mode disable
animation.

Version output records the source revision (or unknown without source metadata).
Source archives can supply GROOVE_BUILD_REVISION as a full commit ID at build time.

FILESYSTEM OVERRIDE:
GROOVE_ALLOW_UNSUPPORTED_FILESYSTEM=1 bypasses filesystem-type qualification.
Use only after verifying local flock, atomic rename and fsync semantics; this
does not bypass ownership, mount or path checks. See docs/operations.md.

DURATIONS AND SIZES:
  --wait 0s scans once; --wait 30s waits up to thirty seconds for capacity.
  --git-timeout 2m is the default positive timeout for Git and lock waits.
  Durations require an integer and ms, s, m or h; bare numbers are invalid.
  --max-file-size defaults to 100M. Bytes or K/M/G (powers of 1024) are accepted,
  including KB/KiB suffixes, case-insensitively. Zero means unlimited.
  Snapshot, config, pool list and completions commands reject --pool.

UPGRADES:
  groove upgrade --check            check stable CLI availability without installing
  groove upgrade --with-plugins     update CLI and supported installed agent plugins
Interactive pool commands can show a daily update notice on stderr. Disable with
GROOVE_NO_UPDATE_NOTIFIER=1 or `groove config set updates.check=false`.
Upgrade works outside repositories and rejects --pool; see upgrade --help.
