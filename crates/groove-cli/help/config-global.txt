
USER PREFERENCES:
  groove config global show
  groove config global set logging.level=trace logging.max_files=50
  groove config global set worktrees.root=/absolute/worktrees
  groove config global unset worktrees.root
  groove config global unset logging.directory
  groove config global edit

Preferences are user-wide, separate from pool settings, and require no repository.
The file is $XDG_CONFIG_HOME/groove/config.toml (or ~/.config/groove/config.toml).
Unset, empty or relative XDG paths use the HOME fallback. `show` reports effective
values and environment overrides. Unknown keys and invalid values fail before
operational commands run. Help remains available with broken preferences.

worktrees.root replaces the default $HOME/.worktrees parent used by new pools:
<root>/<project>-<repo-id>/<pool>. It must be absolute. init --worktree-root
overrides it with an exact pool path. Changing/unsetting this preference never
relocates existing pools; use config show to inspect a pool's recorded path.

The defaults below omit optional worktrees.root and logging.directory:
set it to an absolute path; unset it for $XDG_STATE_HOME/groove/logs (or
~/.local/state/groove/logs). TOML paths do not expand ~. logging.level accepts
error/warn/info/debug/trace and is independent of -v/--quiet. GROOVE_LOG_DIR and
GROOVE_LOG_ENABLED=true|false override file settings. Retention applies to CLI
diagnostics, not managed-worker logs; use history/storage for those.

`set` accepts TOML literals or bare strings, validates updates together and saves
atomically, preserving comments. `unset` restores defaults. Size/count/age limits
must be positive and max_file_mib cannot exceed max_total_mib. Invalid changes
leave the file unchanged.

`edit` uses VISUAL, EDITOR or vi with quoted arguments but no shell evaluation.
Its UI goes to stderr; a validated temporary copy replaces the file only after
success. Invalid edits/editor failures preserve the original; concurrent changes
fail with CONFIG_CONFLICT. Changes take effect on the next invocation. `path`
and `edit` work with broken settings, and global configuration commands create
no persistent diagnostic logs so they can repair the logging destination itself.
