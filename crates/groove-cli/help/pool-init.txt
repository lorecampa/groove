EXAMPLES:
  groove pool init --capacity 4
  groove pool init --capacity 4 --workspace-root /absolute/empty/root
  groove pool init --resume --capacity 4
  groove --pool frontend pool init --capacity 3 --cleanup warm
  groove config set worktrees.root=/absolute/worktrees

Creates slot metadata and permanent locks. Checkouts materialize on demand by
default. --ready-target N enables background preparation of N spare checkouts.
A first commit is required, even with --ready-target 0. Commit the initial files
before init; standalone snapshot commands also work before the first commit.
Running init on a ready pool fails with CONFIG_CONFLICT, even with
identical settings: use `pool show` or `pool set` instead. An interrupted
init resumes automatically with the original settings; --resume is also accepted.
Different settings are rejected with the differing setting named in the error.

Pristine cleanup is the default and removes ignored files on acquisition. Choose
warm only when your workflow validates retained ignored residue; rebuilding a
checkout can discard it. External build-tool caches can also serve pristine pools.

Initializes the selected pool (--pool NAME; default: default). The checkout root
defaults to $HOME/.worktrees/<project>-<repo-id>/<pool> on Linux and macOS.
The project name is sanitized and the ID hashes the canonical common Git directory,
so linked worktrees agree and separate clones of the same project stay separate.
Set worktrees.root in global configuration to replace the ~/.worktrees parent.
--workspace-root overrides it with an exact pool root, without adding components.
Global TOML paths must be absolute and do not expand ~.
Existing pools keep their recorded paths, including legacy roots beneath .git.
The root stays fixed for that pool generation; after destroy, init can choose
another root and settings. Interrupted init must resolve to its original root;
if preferences changed, pass that exact root with --workspace-root when resuming.
A custom root must start empty, be owned by you and lie outside Git administration
and every checkout (the exact legacy state/worktrees root remains accepted).
Roots cannot overlap another pool's root, including pending
and retained deleted pools. Relative paths resolve from the current directory.
Never delete permanent lock files to force setup or recovery.

READY CHECKOUTS:
--ready-target defaults to pool_defaults.ready_target (0) and must be between 0
and capacity. An incompatible global default is rejected; override it explicitly.
--idle-timeout defaults to pool_defaults.idle_timeout (7d); accepts positive whole
s/m/h/d durations or never. Excess idle checkouts become eligible for deletion,
including ignored caches. Slot capacity, permanent locks, branches, snapshots and
release receipts remain. Reservations never expire.
--ready-base defaults to this checkout's HEAD branch, or its commit when detached.
Only local Git state is used; no implicit fetch, build or setup command runs.
The target is best effort: reservations, writers and failures can prevent it.
Acquisition still verifies/prepares the requested revision before returning.

Defaults are copied into this pool, not inherited dynamically. Legacy pools retain
lazy behavior until explicitly configured. Use one supporting Groove version across
this repository: older writers reject enabled pools' new metadata.
Disable automatic work with --ready-target 0 --idle-timeout never.
Use `groove pool show` to inspect background progress and failures.
