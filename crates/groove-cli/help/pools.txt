EXAMPLES:
  groove pools
  groove pools --all
  groove pools --disk-usage
  groove --pool frontend init --capacity 3 --cleanup warm
  groove --pool backend init --capacity 2 --cleanup pristine
  groove --pool frontend acquire --task fix-navigation
  groove --pool frontend destroy --dry-run

Omitting --pool selects default; it never selects a different available pool.
Names are 1..64 lowercase ASCII letters, digits, '_' or '-', starting with a
letter. Pool names are portable across case-sensitive and case-insensitive disks.
All linked worktrees share this catalog. Deleted pools are hidden by default in
both text and JSON output; use --all to include them and find retained history.
Interrupted pools (initializing or deleting) remain visible for recovery.

--disk-usage scans workspace contents (including ignored build outputs), artifact
caches, logs and history for each listed ready or deleted pool. Sizes are logical
file bytes, not allocated or reclaimable blocks; shared Git objects and snapshots
are excluded. Scans can be slow on large pools and may change as writers run.
Interrupted pools show '-' for sizes (storage:null in JSON). Other scan failures
fail the command rather than reporting a misleading zero. Without the flag no
storage scan runs. Interactive stderr shows a spinner while scanning, except with
--json or --quiet; redirected stderr has no animation.

Capacity, cleanup, checkout roots, task labels, request keys, caches, history and
saved-release receipts are scoped to each pool. Keys stay tombstoned across reinit of
that same pool. Snapshots, branches, Git objects and repository configuration are
shared. Pools are not security sandboxes; slot numbers and derived project ports
are pool-local. Managed commands receive GROOVE_POOL for explicit workflow use.

Destroy requires an explicit --pool NAME when several non-deleted pools exist.
--pool-id checks a generation inside that namespace; it does not select a pool.
The original default pool keeps its existing directory and permanent locks.
Named pools live beneath <GIT_COMMON_DIR>/groove/pools/<name>/; their checkout
roots must not overlap another pool's published or pending root. Deleted pools
retain their current root claim until reinitialized with another root.
