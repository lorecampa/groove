EXAMPLES:
  groove snapshot save -m 'before refactor'
  groove snapshot list
  groove snapshot storage --largest 10
  groove snapshot diff ID
  groove snapshot restore ID --to ../recovered
  groove snapshot delete ID

Snapshots save staged and working files, including deletions, modes, symlinks
and non-ignored untracked files, without moving HEAD or touching the real index.
Ignored files and empty folders are excluded. Special files (pipes, sockets and
devices) outside ignored paths are refused because Git cannot preserve them.
Ignored special files are excluded. Export or remove non-ignored special
files before saving; export required ignored
artifacts separately before release --save. No pool, remote or first commit is
required. A working tree is required; bare repositories cannot be captured.
Stop writers first: capture detects common races but is not atomic.
Actual bytes, executable bits and symlinks are preserved independently of Git's
autocrlf/filemode/symlinks preferences. User ignore rules still apply.

Snapshots are shared by all linked worktrees and survive pool reuse. They live in
local refs/groove/snapshots/ and the shared object database; ordinary pushes do
not back them up. Unfinished merges (even without conflicts), rebases, am,
cherry-picks, reverts, bisects, conflicts, submodules,
nested repositories, active content filters,
filter/ident/working-tree-encoding/eol=crlf attributes, intent-to-add and manual
index flags are rejected. Capture checks saved paths; text, legacy crlf and
eol=lf require LF working bytes and byte-preserving staging. CRLF working files
hidden by Git's clean status and lone carriage returns in saved text are rejected.
Saving .gitattributes applies strict whole-tree validation.
Restore validates saved differences from the base against saved and destination
rules. Unchanged converting base paths use ordinary checkout. core.eol cannot
rewrite saved LF bytes. Foreign refs without snapshot UUID names are omitted
from listing; malformed snapshots with valid IDs still fail explicitly.
Unused filter definitions, such as a global Git LFS installation, are harmless.
Concurrent saves wait for the shared lock up to --git-timeout (default 2m).
Use -vv for DEBUG capture/restore phase timings on stderr, including lock waits
and success/error outcomes. Enabled DEBUG file logging retains structured
snapshot_timing records with operation, phase, elapsed_us and outcome fields.
These diagnostics leave --json stdout unchanged. See config show for settings.

SNAPSHOT accepts a full UUID or a unique prefix of at least eight characters.
Ambiguous prefixes fail without selecting a snapshot. Unknown or deleted snapshot
IDs return INVALID_ARGUMENT with "Snapshot not found".

Snapshots pinned by `release --save` or an interrupted in-place restore need
`delete --pinned`. Explicit retention is available with snapshot prune --older-than 30d;
use --dry-run to preview or --yes for noninteractive deletion. Prune never overrides
pins. Deleting removes the ref;
Git reclaims the space during its normal garbage collection.
Unreadable or inconsistent pins cause an error, including with --pinned; repair
the reference before retrying. A reference changed during deletion is preserved.

snapshot diff compares a saved checkpoint with current files (including eligible
untracked files), or with a second checkpoint. It emits an uncolored binary-capable
Git patch with fixed prefixes, independently of Git display preferences. It does
not change HEAD, the real index or working files. Equal trees produce empty output.

snapshot delete accepts multiple IDs; it validates every selector and pin before
deleting. Multiple deletions require terminal confirmation or --yes; --dry-run
previews. Single deletion is immediate. Failed deletion reports any completed IDs.

snapshot list returns at most 50 snapshots, newest first, by default. --pinned
filters to pinned snapshots.
Use --limit 20 --offset 20 for another page, or --unlimited for the complete list.
JSON includes pagination.total, offset, limit (null with --unlimited) and next_offset
(null at the end). Snapshot IDs break ties for equal creation times.
--sort created (default) uses creation time, then snapshot ID; --sort id uses
snapshot ID. --order asc|desc controls the key and its tie-breaker; the default
is desc for created (newest first), asc for id. Sorting precedes pagination.
These options are available on snapshot list only.
Metadata is still enumerated/sorted. Concurrent changes can shift offset pages.
